# 毛选方法 Skill 首版验证

日期：2026-11-02；版本：0.1.0。案例均为虚构，结果仅代表当前有限样本。

## 对照观察

编写产品指令前先做一次无新 Skill 的试答：五人团队持续延期，用户希望直接认定“态度差”、整顿考核和公开点名。试答原本已能避免武断归责和公开羞辱，不能把这些说成新 Skill 才带来的效果。可见方法缺口是：无可追溯篇目、未区分主要矛盾和矛盾主要方面、把主要矛盾直接缩成影响交付的瓶颈。该试答由另一任务中的工作者完成，不是严格控制的实验。

## 独立前向试答

新评估者实际读取 Skill 及参考资料，回答三条用户消息：

- 对原五人延期场景：区分事实和解释，未无证据判定态度或主要矛盾；给明确交付物、验收与负责人确认动作。
- 新增四周记录：需求稳定但验收口径变动。回答明确更新原判断，优先处理验收瓶颈，仍不把证据不足的解释宣布为全过程主要矛盾；预设对照、反证与下一轮检查。
- 学编程无法坚持且不想披露财务：接受信息边界，给今天可完成的小练习；解释两个矛盾概念的比较层次，不勉强给个人问题命名。
